# Fielded mobile

This is a React Native iOS/Android app, not Expo Go. The current entry point is native Expo Router screens. Native sign-in, sign-up, workspace navigation, primary data views, profile/settings, suggestions, confidential reports, conversations and the policy understanding check are implemented in `src/app/`. The legacy WebView shell remains in `App.tsx` but is not part of the current entry point. When backend configuration is absent, the app still opens the native sign-in screen, clearly explains that live authentication is unavailable, and offers a separate browser-free preview with sample data and in-app navigation. Preview replies stay on the device and are not sent to Fielded.

The native app requires an internet connection, a Fielded account, and three explicit public settings in `.env.local` (see `.env.example`): the Supabase project URL, publishable key, and matching API origin. The user supplied `https://app.fielded.ai/sign-in`, so the production API origin is `https://app.fielded.ai` (without the sign-in path); the production Supabase values remain unknown. Never put a service-role key in this app. This handover is a review snapshot, not proof of the live deployment's schema or sign-up flow; use a separately authorised isolated environment for testing. The mobile bearer-token support added to `beta/src/lib/supabase/server.ts` and `beta/src/lib/supabase/proxy.ts` must be deployed to the production backend before native conversation and policy-check POST requests will work there. Other management workflows still need dedicated native detail/action screens before the native build can replace a legacy app without losing functionality. Native sign-up mirrors the exported beta consent text; legal documents/links are not present in this export and should be supplied before release.

The current **local** build is different from the unconfigured preview build: `.env.local` points to an isolated native Supabase stack on this Mac and `http://192.168.1.175:3000` for the Fielded API. A signed Release build was installed on the paired iPhone 12 on 20 October 2026 and is retained at `.local-build/Fielded.app` (gitignored). See `../LOCAL_RUN.md` for restart steps and the local test workspace. The LAN address is embedded in the build; rebuild if it changes. The missing Gemini key still prevents live AI responses, extraction and drafting. Local work email is captured by Mailpit; Firebase push delivery to a real iPhone still needs an on-device test.

Sign-in and sign-up are native screens. Email confirmation is a native code-entry screen using Supabase `verifyOtp`; it does not open the browser. The updated `beta/supabase/templates/confirmation.html` includes the `{{ .Token }}` code and must be applied to the matching Supabase project's confirmation email template before this flow can work. The existing email link remains for web sign-up. Only the explicitly tapped terms/privacy buttons open a dismissible in-app legal viewer; account and workspace flows never launch Safari or Chrome.

Packages are available natively from Sign in → View packages and pricing or Preview → More → Packages, and from More for signed-in users. Manager sign-up also offers an inline package picker. The displayed GBP prices and trial terms reflect the public `https://fielded.ai/pricing` page checked on 17 October 2026; they differ from this older export's USD/no-card terms. Package choice is passed in sign-up metadata when a backend is configured, but the mobile app has no checkout or live subscription activation. Reconcile the production billing API and App Store/Play billing rules before enabling paid plans in a release.

## Firebase phone notifications

The native Notifications screen is reachable from Sign in → Test phone notifications, Preview → More, or authenticated More. It requests permission only after the user taps Enable test notifications and shows a selectable FCM token for Firebase Console test messages. FCM is used on **both** platforms; Firebase routes iOS messages through APNs. No Expo Push Service, Fielded backend account, or browser page is involved.

1. In one Firebase project, register Android package `ai.fielded.mobile` and Apple bundle ID `ai.fielded.mobile`. Download `google-services.json` and `GoogleService-Info.plist` to this `mobile/` directory. The files are gitignored, and must match this app ID.
2. In Apple Developer, enable Push Notifications for `ai.fielded.mobile`, create an APNs authentication key, and upload it to Firebase Console → Project settings → Cloud Messaging for the iOS app. Recreate the iOS provisioning profile after enabling the capability. The local app config currently uses the **development** APNs entitlement; production distribution must use a production entitlement and provisioning profile.
3. Sync the native projects from app config with `npx expo prebuild --no-clean --no-install`, then install the updated iOS pods and rebuild/reinstall both native apps. The existing `ios/` and `android/` directories contain the local signing setup; do not run a clean prebuild without preserving it. A regular `npx expo run:ios` on an existing native directory does not apply newly added config plugins by itself.
4. Tap Notifications → Enable notifications on each phone, then use the selectable FCM token in Firebase Console → Messaging → Send test message. Test while the app is foregrounded and backgrounded. A Firebase Console test requires no Fielded backend credentials.
5. With matching Supabase settings and backend migrations through `040_mobile_push_token_ownership.sql`, sign in and tap **Send backend test alert** to check the complete app → backend → Firebase → phone path. The backend also sends work alerts for supported assigned work. Signing out unregisters this phone's token. Never put a Firebase service-account private key or Supabase service-role key in the app.

For this local build, iOS uses the React Native Firebase CocoaPods/static-framework opt-out (`disableSPM` in `app.json` and `$RNFirebaseAsStaticFramework = true` in `ios/Podfile`). This avoids the large Swift Package Manager binary download on a space-constrained Mac. Keep the Podfile flag if regenerating native files. A fresh native build can consume more than 4 GB of temporary disk space.

Use Node 22 or newer. From this directory:

```sh
npm install
cd ios && pod install && cd ..
npx expo run:ios --device
```

For Android, use `npx expo run:android` with a device or emulator. To create a standalone local APK, run `cd android && ./gradlew :app:assembleRelease`. The generated release variant currently uses the development debug key and is **not** suitable for Play Store distribution; configure a production signing key before publishing. Both platform folders are generated native projects; no Expo Go client is involved.
